    Nguyên tắc và phạm vi

    Giới hạn bắt buộc: nếu plaintext được đưa vào environment của agent hoặc process do agent kiểm soát, agent có thể đọc hoặc in nó ra. Cam kết “dùng mà không thấy” chỉ đúng khi thao tác được trung gian hóa bởi trusted broker.

    Mục tiêu

    • Không còn secret plaintext trong repository và shell profile.
    • Một secret có một nguồn sự thật duy nhất.
    • Scope dạng cây với kế thừa và override minh bạch.
    • Unlock một lần cho phiên làm việc, tự khóa an toàn.
    • Agent dùng capability bị giới hạn thay vì nhận secret.
    • Audit metadata mà không rò rỉ nội dung nhạy cảm.
    • Import, rotate, revoke và recovery có quy trình rõ ràng.

    Phi mục tiêu

    • Không chống lại root, kernel compromise hoặc malware toàn quyền cùng user.
    • Không thay thế cloud secret manager cho production workload.
    • Không cung cấp account hoặc dịch vụ đồng bộ cloud. Portability chỉ qua file export/import do người dùng chủ động quản lý.
    • Không hứa bảo vệ secret sau khi trusted application tự log nó.
    • Không cho plugin tùy ý chạy trong daemon process.
    • Không tự động sửa repository hoặc xóa file secret khi chưa có xác nhận.

    Nguyên tắc thiết kế

    P1

    Deny by default

    Mọi capability cần policy rõ ràng, scope cụ thể và thời hạn ngắn.

    P2

    Least privilege

    Chỉ cấp đúng action, resource, host và method cần thiết.

    P3

    No plaintext persistence

    Không ghi plaintext vào disk, log, crash report hoặc clipboard mặc định.

    P4

    Explicit trust boundary

    Daemon nhỏ, không extension runtime, bề mặt tấn công tối thiểu.

    P5

    Portable core

    Core logic độc lập OS, adapter riêng cho keychain, socket và process.

    P6

    Safe UX

    Trạng thái khóa, scope hiệu lực và quyền đang cấp luôn nhìn thấy được.

    Explicit activation: EnVault chỉ phục vụ secret sau khi envault start đã khởi động daemon và auth thành công. Không command nào khác được âm thầm start hoặc unlock daemon.

    Mật mã và vòng đời key

    flowchart TD
  Password["Master password"] --> KDF["Argon2id"]
  KDF --> KEK["Key Encryption Key"]
  Device["OS Keychain binding\nOptional"] --> Unlock["Unlock material"]
  KEK --> Unwrap["Unwrap Vault Master Key"]
  Unlock --> Unwrap
  VMK["Wrapped Vault Master Key\nStored in DB"] --> Unwrap
  Unwrap --> RAM["Vault Master Key\nRAM only"]
  RAM --> WrapDEK["Wrap / unwrap DEK"]
  DEK["Random DEK per secret version"] --> WrapDEK
  DEK --> AEAD["XChaCha20-Poly1305"]
  Plain["Secret plaintext"] --> AEAD
  AEAD --> Cipher["Ciphertext + nonce + AAD"]

    Key hierarchy

    1. Password tạo KEK qua Argon2id với salt riêng.
    2. KEK chỉ unwrap Vault Master Key.
    3. Mỗi version của secret có DEK ngẫu nhiên riêng.
    4. DEK mã hóa plaintext và được VMK wrap.
    5. Rotation VMK chỉ re-wrap DEK, không cần giải mã toàn bộ secret.

    Associated data

    AAD phải bind ciphertext với vault ID, secret ID, version, scope ID và algorithm version để chống tráo bản ghi.

    Memory discipline

    Dùng buffer có zeroization, tránh clone, giới hạn thời gian plaintext trong RAM, không đưa secret vào panic message và cân nhắc mlock theo platform.

    AEAD
    XChaCha20-Poly1305
    Nonce ngẫu nhiên 192-bit
    Password KDF
    Argon2id
    Tự hiệu chỉnh theo thiết bị
    Randomness

    Không mã hóa nhưng tối thiểu hóa

    Schema version, ciphertext length, timestamps, opaque IDs và trạng thái migration có thể để plaintext để vận hành database. Tên secret, scope path và policy resource nên được mã hóa nếu threat model coi metadata là nhạy cảm.

    Ràng buộc dữ liệu

    Unique theo (scope_id, normalized_name), foreign key bật bắt buộc, mọi mutation dùng transaction, audit append-only có chain hash để phát hiện chỉnh sửa cục bộ.

    Description metadata cho agent discovery

    Profile và secret có description được mã hóa at rest. Agent chỉ thấy metadata của resource mà principal hiện tại có quyền discover, không thể dùng description API để suy ra sự tồn tại của secret bị cấm.

    Profile metadata

    name: base
    description: API credentials used across personal development projects
    activate_on_start: true
    scope: user

    Secret discovery metadata

    name: OPENAI_API_KEY
    description: OpenAI API credential for model and response requests
    provider: openai
    capabilities: [openai.responses, openai.models]
    Quy tắcThiết kế
    Độ dàiDescription tối đa 240 ký tự UTF-8, một câu ngắn, không dùng làm tài liệu dài.
    OptionalityDescription luôn optional cho cả profile và secret, kể cả startup profile. Không có description không làm resource invalid.
    Agent fallbackAgent ưu tiên capabilities[], rồi provider, name, cuối cùng mới dùng description nếu có.
    VisibilityCần quyền metadata.discover; danh sách chỉ gồm resource đã được policy lọc.
    Secret scanningTừ chối hoặc cảnh báo description chứa giá trị giống credential, entropy cao hoặc known secret value.
    Prompt safetyDescription là untrusted data, không phải instruction. Agent skill phải cấm làm theo command hoặc URL được nhúng trong description.
    VersioningMọi thay đổi description được audit và tăng metadata generation, không tạo secret value version mới.

    Scope, kế thừa và resolution

    flowchart TD
  User["user:thanhbinh"] --> Workspace["workspace:envault"]
  Workspace --> Project["project:cli"]
  Project --> Dev["environment:dev"]
  Project --> Test["environment:test"]
  Dev --> Task["task:agent-session-42"]

  User -. "GITHUB_TOKEN" .-> Workspace
  Workspace -. "OPENAI_API_KEY" .-> Project
  Dev -. "DATABASE_URL override" .-> Task

    Thuật toán resolution

    1. Chuẩn hóa principal, workspace và context hiện tại.
    2. Xây chain từ leaf scope về root.
    3. Tìm secret cùng logical name từ leaf lên root.
    4. Áp dụng tombstone để chặn kế thừa khi cần.
    5. Kiểm tra policy trên secret đã resolve.
    6. Trả về opaque reference, không trả plaintext.
    7. Ghi decision trace đã redaction để giải thích vì sao rule match.

    Quy tắc bắt buộc

    Explicit override: UI và CLI phải hiển thị secret đến từ scope nào và scope nào đang override.
    Tombstone: scope con có thể chặn kế thừa mà không cần tạo giá trị giả.
    No ambient context: daemon không tự đoán project chỉ từ current directory của chính daemon.
    Canonical identity: symlink và path alias phải resolve về workspace ID ổn định.
    07

    Native agent commands theo AXI

    Agent không cần SDK, MCP server hoặc lớp integration riêng. Agent gọi trực tiếp cùng executable envault như developer, còn daemon vẫn là security boundary giữ secret và thực hiện hành động được ủy quyền.

    Áp dụng AXI: AXI được dùng như contract thiết kế CLI agent-ergonomic, không phải một transport mới. Command phải token-efficient, deterministic, non-interactive, có structured errors, output giới hạn và gợi ý next step. Nguồn: axi.md và kunchenguid/axi.
    sequenceDiagram
  autonumber
  participant A as AI Agent
  participant C as envault AXI CLI
  participant D as envaultd
  participant P as Policy Engine
  participant B as HTTP Broker
  participant X as External API

  A->>C: envault request http --profile openai --input request.json
  C->>D: create_capability(action, host, method, scope)
  D->>D: Xác thực peer + session
  D->>P: evaluate(principal, action, resource, constraints)
  alt Cần human approval
    P-->>D: prompt approval
    D-->>C: pending + approval_id + next command
    C-->>A: structured pending result
  else Bị từ chối
    P-->>D: deny + reason code
    D-->>C: denied
  else Được phép
    P-->>D: allow with TTL and limits
    D-->>C: opaque capability handle
    C->>D: execute(handle, sanitized request)
    D->>B: resolve secret internally
    B->>X: inject Authorization header + send
    X-->>B: response
    B->>B: size limit + redact + content policy
    B-->>D: bounded structured response
    D-->>C: bounded TOON result without credential
    C-->>A: usable structured result + help[]
  end

    Capability fields

    • Principal ID
    • Secret reference
    • Adapter + action
    • Allowed host/path/method
    • Request count và byte limit
    • Expiry, nonce, approval ID

    Response firewall

    • Không follow redirect sang host khác
    • Giới hạn response size
    • Redact known secret variants
    • Chặn header nhạy cảm
    • Structured allowlist output
    • Không trả raw TLS debug

    Human approval

    • Always, once, session, policy
    • Hiện host và action cụ thể
    • Không hiện plaintext
    • Timeout ngắn
    • Không có wildcard mặc định
    • Có nút revoke tức thì

    AXI contract cho envault

    Content first

    Không có argument thì hiện vault state và scope hiện tại, không chỉ hiện help.

    TOON output

    Schema nhỏ, ổn định, dễ parse và tiết kiệm context.

    Fail loud

    Unknown flag exit 2, error có code và không chứa secret.

    Non-interactive

    Agent mode không prompt. Approval trả ID để human xử lý riêng.

    Next steps

    Mọi output có help[] với command tiếp theo hợp lệ.

    Installable Agent Skill

    EnVault phát hành một skill ngắn, runtime-aware và không chứa secret metadata tĩnh. Skill dạy agent cách discover description/capability, xử lý inactive state và sử dụng broker mà không yêu cầu plaintext. Package tương thích với npx skills.

    npx skills add <owner>/envault --list
    npx skills add <owner>/envault --skill envault -g -a codex -a claude-code

    Project install là mặc định. -g dùng cho global install; -a chọn agent đích.

    name: envault
    description: Use EnVault when an agent needs scoped credentials, environment profiles, or authenticated provider operations without reading plaintext secrets.

    UUID v4

    Độ dài cố định

    --generate uuid-v4 tạo chuỗi canonical 36 ký tự, gồm dấu gạch nối, với 122 bit ngẫu nhiên. Không nhận --chars.

    Base64URL

    Ưu tiên cho token

    --format base64url --bytes 32 cho 43 ký tự không padding và 256 bit entropy. --chars 64 tạo đúng 64 ký tự từ alphabet URL-safe, tương đương 384 bit entropy.

    Base64

    Tương thích chuẩn

    --format base64 --bytes N dùng alphabet chuẩn và padding. Độ dài output là 4 * ceil(N / 3), nên không hỗ trợ --chars để tránh semantics mơ hồ.

    Default khuyến nghị: base64url --bytes 32. CLI chấp nhận 1 đến 4096 bytes hoặc ký tự; dưới 22 ký tự phải fail mặc định và chỉ cho phép bằng --allow-weak kèm cảnh báo rõ.
    envault secret value generate APP_SECRET --format base64url --chars 64
    secret: APP_SECRET · version: 2 · generator: base64url · chars: 64 · entropy_bits: 384 · value: redacted
    envault secret create INSTANCE_ID --generate uuid-v4
    secret: INSTANCE_ID · version: 1 · generator: uuid-v4 · chars: 36 · value: redacted
    Không nhận plaintext qua argv: không có --value, positional value hoặc environment variable đầu vào vì có thể lọt vào shell history, process list và telemetry. Human dùng masked TTY prompt hoặc --stdin; agent không được mở prompt và không có đường đọc value sau khi tạo.
    Quy tắc rename và external references
    • --preview không mutate và trả machine-readable impact report.
    • Commit rename là atomic và fail khi alias mới collision trong cùng namespace.
    • Bindings, policies và audit dùng UUID nên tự giữ nguyên hiệu lực.
    • EnVault không tự sửa source code, file .env, CI config hoặc tên biến ở hệ thống ngoài vault.
    • Nếu rename làm thay đổi tên env được inject, preview phải cảnh báo external consumers có thể cần migration thủ công.
    IPC API nguyên tắc
    • Protocol versioned, ưu tiên length-delimited binary hoặc JSON có schema chặt.
    • CLI kiểm tra socket trước. Socket không tồn tại trả envault_not_running, socket tồn tại nhưng chưa auth trả envault_locked.
    • Mọi lỗi inactive đều có help[]: Run `envault start`. Không command nào được implicit start daemon.
    • Mỗi request có request ID, deadline, client identity và context đã ký bởi session.
    • Error dùng machine-readable code, không nhúng dữ liệu nhạy cảm.
    • Peer credential phải được lấy từ OS, không tin user ID do client tự gửi.
    • Streaming bị tắt trong MVP trừ khi adapter có response firewall đầy đủ.
    • Không có method generic như eval, exec hoặc get_secret.

    Workspace và profile portability

    EnVault hoàn toàn local. Export và import là thao tác chủ động trên file do người dùng kiểm soát, không có account, server hoặc background synchronization. Profile package và workspace package dùng chung một versioned encrypted container.

    Profile

    *.envault-profile

    Chứa một hoặc nhiều profile, scope cần thiết, secret bindings và policy được chọn.

    Workspace

    *.envault-workspace

    Chứa workspace metadata, scope tree, profiles, secret versions, bindings, policies và tombstones.

    Protection

    Transfer key slots

    Package key được bảo vệ bằng transfer password Argon2id hoặc recipient public key. Không chứa source Vault Master Key.

    Plaintext

    Explicit escape hatch

    Export `.env` chỉ dành cho human, cần admin auth, flag rõ, permission 0600 và không bao giờ là default hoặc agent-accessible.

    Profile tự động active khi start

    Mỗi vault có đúng một profile với activate_on_start: true. envault init tạo profile mặc định tên base và bật boolean này. envault start chỉ trả thành công sau khi daemon chạy, auth thành công và profile được đánh dấu đã được activate.

    Invariant

    Exactly one boolean true

    Một vault không có hoặc có nhiều profile activate_on_start: true là invalid state.

    Activation

    Metadata only

    Activate chỉ load scope graph, bindings, policy references và generation. Không decrypt toàn bộ secret value.

    Failure

    Fail closed

    Profile missing, corrupt hoặc policy-invalid làm envault start thất bại. Service không chuyển sang active một phần.

    envault profile show base
    profile: base · activate_on_start: true · id: prf_01... · generation: 7
    envault profile update personal --activate-on-start
    admin_auth: required · help: envault admin unlock
    Atomic switch: --activate-on-start atomically đặt profile được chọn thành true và profile cũ thành false. Không có command bỏ cờ trên profile cuối cùng mà không chọn replacement.
    Runtime behavior: sau khi envault start thành công, profile có activate_on_start: true là base profile cho mọi unpinned session. Session profile có thể override hoặc extend theo policy.
    Import safety: package có thể mang giá trị activate_on_start để preview, nhưng import mặc định không thay đổi boolean của vault đích. Việc adopt profile imported làm auto-activate cần flag rõ và admin auth.

    No autostart by default

    Không có process sau khi login. envault start mới khởi động daemon và auth.

    Event-driven idle

    Daemon block trên local socket và OS events, không polling filesystem, profile, TTL hoặc network.

    Service không TTL

    Sau khi auth, service và profile có activate_on_start: true tồn tại đến stop, lock, logout hoặc shutdown.

    Admin TTL riêng

    Reveal, add, edit, delete, plaintext export và policy escalation yêu cầu admin auth ngắn hạn.

    Backup

    Snapshot nhất quán từ SQLite, đã mã hóa, có manifest và checksum. Không backup unlocked memory.

    Recovery

    Recovery kit tạo khi init, xác nhận người dùng đã lưu. Mất password và recovery key đồng nghĩa mất dữ liệu.

    Upgrade

    Format version độc lập app version, migration copy-on-write, kiểm tra rollback trước commit.

    Quyết định kiến trúc đã chốt

    Architecture baseline v1.0 đã được người dùng phê duyệt ngày 2026-07-30. Thay đổi các quyết định dưới đây sau khi triển khai bắt đầu phải được ghi bằng ADR mới.

    D1 đã chốt: tên chính thức của sản phẩm và executable là EnVault / envault. Daemon dùng tên envaultd.
    Lifecycle đã chốt: mặc định không autostart. envault start khởi động daemon và auth; mọi command khác fail loud nếu service chưa active. Service và auto-activated profile không có TTL.
    Auto-activate đã chốt: mỗi vault có đúng một profile với activate_on_start: true, mặc định là base. Không sử dụng profile role.
    Portability đã chốt: *.envault-profile và *.envault-workspace dùng versioned encrypted package, DEK re-wrapping, preview bắt buộc và atomic import.
    Agent discovery đã chốt: description là optional cho mọi profile và secret. Nếu có, description được mã hóa; agent chỉ thấy policy-filtered metadata và capability, không thấy value.
    Agent Skill đã chốt: repository phát hành skill tên envault, cài bằng npx skills add <owner>/envault --skill envault.
    Mutation contract đã chốt: profile và secret có lệnh rename giữ nguyên UUID; set hoặc generate value luôn tạo version mới. Generator hỗ trợ UUID v4, Base64URL và Base64 với length semantics rõ ràng, dùng CSPRNG và không echo plaintext.
    Unlock mặc định đã chốt: master password là recovery root; OS keychain là tùy chọn để cải thiện UX trên thiết bị tin cậy, không thay thế recovery bằng password.
    Native adapter đầu tiên đã chốt: envault request http với OpenAI profile là lát cắt đầu tiên để chứng minh agent-blind broker và response firewall.
    Session activation đã chốt: agent đang chạy đổi profile qua daemon session binding, không sửa environment của process và không cần restart agent.
    Human interface order đã chốt: CLI hoàn thiện trước, tiếp theo là envault-tui, sau đó mới phát triển desktop UI. TUI và UI chỉ là IPC clients, không sở hữu crypto key hoặc business rules riêng.
    Change control: plan đã final. Các thay đổi sau đây không chỉnh âm thầm vào baseline mà phải có ADR nêu context, decision, alternatives, security impact và migration path.

    Architecture đã final, sẵn sàng triển khai

    Khởi tạo Git repository, viết threat model và ADR thành tài liệu chuẩn, tạo Rust workspace theo boundary ở trên, sau đó hoàn thành Phase 1 bằng một lát cắt init → start/auth → create/generate secret → rename → versioned value change → stop → start/auth → broker use → stop.
